# 专业仿真工作台：设计与实施计划

## 产品目标
在保持专业性的前提下，降低使用门槛，让非 SPPARKS 专家也能快速理解输入项并启动仿真。

## 本轮设计
依据用户标注图采用单页工作台，上方左侧物理定义、右侧计算平台，下方运行控制台与可视化。缩小宣传性标题，采用紧凑、清晰的工程界面，使用深色导航与控制台、浅色参数区域、青色状态强调。

物理定义按模型、激励、格点/状态组织。三个现有案例没有具体元素质量、原子势或分子组成输入，不提供伪配置；明确标注粗粒化状态。温度保持模型单位，薄膜沉积率保持模型量。每项参数说明作用、范围和单位，默认值可直接运行。

平台信息区区分宿主机资源和求解器实际资源。CPU 型号、物理核、逻辑处理器、总内存及采样时可用内存来自本机检测，失败显示未获取。当前串行执行固定一个进程、一个计算线程，不提供无效的多核配置；内存为系统动态分配，检测值不代表任务占用或配额。

控制台包含终止时间、随机种子、启动按钮、运行状态、已输出模型时间、真实日志尾部。只在成功后加载结果，保留失败日志；明确旧结果回放与正在计算的区别。回放控制位于可视化内，不伪装成求解器暂停。

保留三案例切换、剖切、拾取、视角、时间轴、曲线、对比、导入导出与展示模式。运行期间锁定输入，结果参数与待运行输入发生变化时提示。窄屏按物理→平台→运行→结果顺序堆叠。

## 实施计划
1. 建立模型物理信息和参数帮助元数据，更新产品目标。
2. 新增平台检测接口与有界日志读取，串行资源口径固定。
3. 重组页面区块，实施专业工作台视觉体系。
4. 接通模型选择、参数说明、输入变更提示、运行状态与日志。
5. 自动验证检测/日志逻辑和已有适配器；运行真实算例并验证浏览器操作与窄屏。
6. 更新 PROJECT_PLAN、使用说明及验证记录，交付本地可运行版本。

## 验收
非专家可以从参数说明理解格点、状态、模型温度和终止时间；按 01–04 顺序完成一次真实运行。硬件数字必须是真实检测值或明确未知。三个模型输出含义与原有算法保持一致。不扩展 MPI、集群调度、原子势建模和任务终止能力。
